# 地图行动页的邀请与接受流程

本页记录2026-10-13用户追问“列表入口是什么、接受救助页面呢”后补充的视觉规格。仍处于概念审阅阶段，未修改SwiftUI、请求协议、任务状态机或手机安装包。

## 列表入口的真实含义

`NearbyVolunteersView.listContent`只显示不同统计半径内的累计人数，没有个人名单、个人坐标或可挑选的救助事件。第一张待命稿的底部面板已直接展示这些人数，因此本轮建议移除重复的列表按钮；这是待用户确认的设计提案，不表示已删除现有功能。

## 三个主要页面状态

| 状态 | 地图 | 底部内容与主要操作 |
| --- | --- | --- |
| 待命 | 本人位置与人数统计范围圈 | 附近累计人数、上报发现的患者；正常待命状态卡隐藏 |
| 收到有效求助邀请 | 只保留本人位置，不展示患者精确点、地址、招募圈或路线 | 事件类型、距离区间、预计用时区间、搜索半径、接受倒计时；暂不参与 / 接受响应 |
| 已接受且已确认分配任务 | 依据服务端分配展示当前目的地与步行路线 | 当前阶段、位置说明、对应阶段操作、地图导航、协作团队及更多操作 |

收到邀请后，行动页切换到邀请状态，不需要通过列表入口进入。邀请是独立的决策状态：隐藏待命人数与上报按钮，继续沿用当前邀请页隐藏tab bar的规则；不因点击背景、滑动或超时自动接受。

邀请没有患者坐标，不能擅自把招募圈画在本人位置上。原始邀请图沿用了待命三圈，容易与卡片中的1000米招募范围混淆；最终稿移除邀请地图上的范围圈与半径文字，搜索范围只在邀请卡片说明。

## 接受过程与异常

- 邀请实际可见时保留`markResponseRequestViewed`触发点，以及DELIVERED→VIEWED回执和服务端确认门禁。VIEWED尚未确认时展示等待反馈，不能用地图加载或按钮点击替代回执。
- 点击“接受响应”或“暂不参与”后等待服务器确认；不能乐观进入任务或待命。请求提交期间避免重复点击；失败保留邀请及既有错误反馈，并按原有效期判断是否仍能接受。当前旧实现没有独立提交中禁用，这属于待实现的UI保护，不是已验证行为。
- 已接受但尚未取得分配任务时，显示紧凑的等待状态。没有任务回执不能凭本地推断角色、目的地或患者位置。
- 邀请剩余时间由服务端`expiresAt`计算，按秒更新，不重置或延长。过期清理、失效通知和REST对账沿用既有机制；当前视觉倒计时归零本身不会清理请求，不能伪造服务端回执或任务终态。拒绝仅在服务端确认后进入对应状态。
- 新视觉中的具体地址、路线和倒计时都是标识过的示例，不能作为真实任务数据。

## 接受后的两种分工

服务端决定`GO_TO_PATIENT`或`FETCH_AED`，不增加手动选择角色。

| 分工与当前状态 | 主操作 |
| --- | --- |
| 任一分工 / assigned | 开始前往 |
| 前往患者 / enRoute，或取AED / enRouteToPatient | 已到达患者 |
| 取AED / enRoute | 已到达 AED |
| 取AED / arrivedAtAed | 确认已获取 AED |
| 取AED / aedAcquired | 携 AED 前往患者 |
| 任一分工 / arrivedAtPatient | 确认已完成现场交接 |

任务概念稿选取`GO_TO_PATIENT + assigned`示例，因此按钮为“开始前往”。取AED沿用相同地图和面板骨架，目的地、阶段与操作按上表变化；不能合并“已到达AED”和“已获取AED”。

“更多”承载当前可用的退出操作，保留原门禁、确认次数与重试；AED不可用、15秒改派确认以及任务终态不能因视觉收拢而丢失。地图导航继续沿用高德优先、未安装或唤起失败时Apple地图回退。

现有`LiveRouteMap`只展示本人和目的地标记，步行路线需打开外部地图导航。任务图中的蓝色线路是重构提案，需要未来通过真实MapKit路线绘制；不可使用图片里的固定折线代替真实路线，也不能将概念图解释为当前手机已有的功能。

## 必须保留的业务与展示位置

以下是对三张主要状态图的补充约束，不改变业务协议或服务端权限；所有既有功能都必须能在新布局中到达。

| 业务 | 新布局保留方式 |
| --- | --- |
| 最近事件结果 | 隐藏正常待命卡时，将原`last-patient-outcome`迁移为待命地图上的紧凑结果提示；不能把误报、取消、结束或其他终态都统称为已完成 |
| 附近人数刷新与有效期 | 保留进入待命时首刷、离开时清理及等价手动刷新入口（人数面板标题旁“刷新”）；继续用原协调器取消旧请求并隔离会话/请求代次，按原每5秒显示检查及120秒有效期处理失效值，未知不得显示成0人 |
| 正常/异常待命状态 | 只隐藏正常“可以接收附近求助”；连接失败、定位无效、数据不可用仍在地图上方以紧凑文字提示，范围圈偏好和回到当前位置继续有效 |
| 上报发现的患者 | 保留业务授权与有效定位门禁、提交中状态和二次确认及原后果说明；收到邀请或执行任务时不误露出待命上报按钮 |
| 响应状态汇总 | 在任务面板保留可展开的“响应状态”，显示已响应、出发中、已到达、已取AED人数；已接受尚无任务时该汇总也按原资格保持可达 |
| 患者位置详情 | 面板地址下面保留楼层和进入说明；缺失时沿用真实占位，不以概念图示例补齐。AED仅展示已有取用点坐标与元数据，不伪造名称、楼层或开放情况 |
| 算路与导航异常 | 保留算路中/失败提示、位置或路线不可用说明、外部地图唤起失败alert与导航回退，不能因地图常驻而伪装为已获得路线 |
| AED阶段操作 | 到达AED、获取AED、携AED前往患者保持独立按钮与回执；AED不可用只在原允许的阶段显示，不能从图未画推断删除 |
| 改派及结果 | 提案提示置于任务面板上方，保留15秒倒计时、接受/继续原任务、提交中禁用，以及接受、拒绝、超时和服务端拒绝原因的结果反馈；服务器确认前保持原任务 |
| 协作团队 | 原入口继续打开现有匿名团队页，保留匿名编号、角色、状态、位置新鲜度、六个封闭预设消息与加载/空态/重试/发送失败反馈；不新增自由聊天或成员精确点 |
| 退出与重试 | “更多”仅收纳原退出操作，仍按`canExitCurrentEvent`门禁显示；所有响应者退出均需原三次确认，取消/关闭从头开始。退出失败重试按原exitID继续，独立重试入口不能因任务按钮被隐藏而消失 |
| 任务终态 | 保留完成、AED不可用、取消和超时等原结果；任务完成/AED不可用不自动等同退出事件参与，终态下按原规则提供团队及可用退出入口 |
| 全局反馈与安全说明 | 保留RootView错误alert、模拟事件/受控账号标识，地图不能盖住它们。沿用完整SafetyBanner文案：“志愿协作不能替代专业急救，也不提供救护车调度，不会自动拨打急救电话。”；图中的缩写不作为删减文案的授权 |

地图重构仅替换中立待命与响应者页面。RootView的身份恢复、登录、协议、权限门禁和患者独立分支保持；患者状态优先。患者页的状态确认截止时间与继续救助、三次取消确认、误报/结束确认、响应汇总及终态/同步中提示保持。权限不足时仍能进入设置阅读协议和管理账号；救助期间账号操作继续按原门禁限制。

启动动画不能挡住求助、任务、待处理通知或错误；通知继续只触发权威状态回读，不因通知或地图交互自行接单、分工或导航。真实位置、分工、AED占用/领取及任务终态的权威仍在原业务层/服务端，地图只负责展示。

### 当前既有缺口与验证边界

- `LocationCardView`与`AppStore.speakLocationCard`均已存在，但当前页面没有实例化/调用；UI提交之前也未接线。该旧有朗读入口缺口不归因于本轮地图方案，也不能被列为当前可用功能已通过核对。
- 提交中防重复点击、已接受但暂无任务的等待面板是新UI计划补充的反馈；当前源码尚未实现，不把设计约定当成已通过测试。
- 本轮核对是源文件/快照、设计规格及测试源码检查，没有运行新的构建、模拟器、真机业务或救助事件。实现后仍需用离线UI回归覆盖上述状态、完整AED链、三次退出/重试、响应汇总、人数失效、患者优先及大字体/深色，才能确认实际重构未回归。
